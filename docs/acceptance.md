# Приёмка

CI этого репозитория проверяет генератор и installer на синтетических данных.
Отдельный job проверяет [настоящий HA runtime с моделируемым AMI](runtime-verification.md).
Оно не подтверждает состояние вашей сети, HA, PBX или телефона. Живую приёмку
проводят отдельно, без секретных DTMF и без внешних номеров.

## 1. Пакет и установка

- Hash/размер/manifest проходят, staging содержит только компонент Asterisk.
- Без `--apply` HA config остаётся неизменным.
- Backup и откат доступны, HA config check проходит, выбранный HA Pod готов.
- Integration Asterisk подключается к ровно одному PBX с указанным account.

## 2. Discovery и состояния

- Для двух существующих PJSIP endpoint появились Registered, State,
  Connected Line, DTMF Sent/Received. Все ID сверены вручную.
- Физический offline/online телефона сопоставлен с PBX contacts и HA state.
- Начало, соединение и завершение разговора меняют наблюдаемые состояния.
- После временного отключения AMI соединение восстанавливается, свежесть
  sensor проверена настоящим событием, а не только загрузкой интерфейса.

## 3. Управление

- `asterisk_call_pair` звонит исходному 201. После ответа звонит 202.
- Отмена подтверждения в dashboard не начинает вызов.
- PBX с `allow_originate:false` отклоняет Originate. Это не делает аккаунт
  полностью read-only: Hangup/ModuleLoad входят в `system`.
- Во время соединённого вызова Channel соответствует этому endpoint.
- Hangup завершает только выбранный живой канал. Idle/None/чужой Channel
  не проходят защитное условие. При одновременных вызовах Connected Line
  может быть недостаточен: сверяйте полный список на PBX.

## 4. DTMF

- Во время 201↔202 нажмите выбранную тестовую цифру на каждом аппарате по очереди.
- Запишите, какой фактический Sent/Received sensor изменил timestamp и Digit.
- Скорректируйте mapping, включите notification automation и повторите тест.
- Появляется только локальное уведомление; никаких бытовых действий не происходит.
- Повторная такая же цифра тоже определяется новым timestamp. Перезагрузка HA
  сама по себе не должна воспроизводить старое DTMF как новое действие.
- Верните automation в выключенное состояние после обучения/пилота при необходимости.

## 5. Assist 630

- Pipeline отвечает в интерфейсе HA до подключения телефона.
- На PBX подтверждены оба пути transcoding G.711↔Opus реальными образцами аудио
  или живым вызовом. Формат `opus` без codec/translation не считается успехом.
- Телефон вызывает 630, устройство VoIP получает правильный From extension.
- После разрешения звонков запрос распознаётся и ответ слышен по телефону.
- Проверены оба направления RTP, повторный звонок, hangup и отсутствие зависшего канала.
- Для заявленного локального режима STT/agent/TTS не передают запросы в облако.

## Запись результатов

Храните результаты локально: дата, версии HA/PBX/upstream, образ/digest codec,
проверенные пункты и дефекты. Не прикладывайте CallerID, реальные IP, AMI secret,
аудио жильцов или DTMF-последовательности в публичный issue. Для отчётов используйте
обезличенный пример с минимальным числом событий.
